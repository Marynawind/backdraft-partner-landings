# Публикация страницы /Meprolight в BigCommerce

## Почему обычная страница BigCommerce, а не внешний сервер

Страница — это только HTML + CSS, без backend и без JS, и вся целиком, вместе
с картинками, лежит в одном файле `bigcommerce-page.html`. Он помещается в поле
«Page Content» BigCommerce: вставил код — и всё, загружать в магазин отдельно
нечего. Внешний хостинг с кнопкой-редиректом делать
не нужно и вредно: уход на чужой домен рвёт сессию и корзину покупателя,
SEO-вес уходит не на backdraftsuppressors.com, а партнёру приходится давать
ссылку на посторонний домен вместо обещанного `backdraftsuppressors.com/Meprolight`.

## Порядок публикации (5 минут, через админку)

1. **Storefront → Web Pages → Create a Web Page**
2. Page Type: **Contains its own content** (не «Link to…»)
3. **Page Name:** `Meprolight Optics`
4. **Page Content** → нажать кнопку источника HTML (`<>` / «Source code» в TinyMCE)
   и вставить **всё содержимое `bigcommerce-page.html`** целиком.
   ⚠️ Только в режиме HTML-источника — визуальный редактор вырежет `<style>`.
   Файл около 200 КБ (в нём зашиты картинки), окно вставки может подтормозить —
   это нормально, дождаться и сохранить.
5. **Navigation Menu Options** → снять галку «Show this web page in the navigation menu».
   Страница нужна только по прямой ссылке для клиентов Meprolight.
6. **Page URL / SEO** → задать URL вручную: `/Meprolight`
   (по умолчанию BigCommerce слепит адрес из названия страницы —
   получится что-то вроде `/meprolight-optics/`).
7. **Page Title (SEO):** `Meprolight Optics Customers — Free Suppressor Rebate | Backdraft Suppressors`
   **Meta Description:** `Meprolight Optics customers: redeem your Free Suppressor Rebate on a 4" Hunter Suppressor at Backdraft Suppressors. Four redemption steps and full rebate terms.`
8. Save → открыть `https://backdraftsuppressors.com/Meprolight`.

### Регистр в URL
BigCommerce приводит адрес к нижнему регистру: страница откроется как
`backdraftsuppressors.com/meprolight`, ссылка `/Meprolight` на неё отработает.
Партнёру можно давать `backdraftsuppressors.com/Meprolight`.

## Картинки

Обе картинки зашиты прямо в `bigcommerce-page.html` как data URI, поэтому
**загружать ничего не нужно** — ни в Image Manager, ни по WebDAV. Страница
работает сразу после вставки и не зависит ни от чьего CDN.

Плата за это — вес: base64 добавляет треть сверху, файл получается около 200 КБ.
Поэтому `page.src.html` написан так, чтобы каждый файл упоминался ровно один раз
(`build.py` проверяет это и падает, если ссылка задвоилась); иллюстрация в шапке
выводится CSS-фоном, а не тегом `<img>`, чтобы маска блика переиспользовала ту же
переменную, а не тащила вторую копию тех же 58 КБ.

Если позже захочется облегчить страницу — картинки можно вынести на CDN магазина
(Image Manager или WebDAV в `/content/`) и заменить в `page.src.html` пути
`assets/…` на боевые URL, а сборку пропустить. Но тогда файл перестанет быть
самодостаточным, а порядок публикации усложнится на один шаг.

### Почему картинки больше не берутся с CDN Outlier

Раньше иллюстрации подключались по прямым ссылкам на `dhgf5mcbrms62.cloudfront.net`.
Это были исходники «латунь по чёрному фону», и чёрный прямоугольник прятался
CSS-трюком `mix-blend-mode: screen`. У трюка два ограничения: он работает только
пока картинка лежит на чёрном, и он запрещает любой transform на родителе —
transform создаёт stacking context, блендинг отключается и чёрный квадрат
возвращается. Из-за этого иллюстрацию нельзя было анимировать.

Теперь в `assets/` лежат вырезанные версии с настоящей прозрачностью — их
делает `tools-cutout.py` из исходников в `assets/source/`. Скрипт вычитает фон,
берёт альфу из яркости и делает un-premultiply, то есть выполняет точную
инверсию screen-блендинга: на тёмной странице результат неотличим от прежнего,
но фон больше не нужен и картинку можно двигать.

Файлы с прозрачностью весят больше исходников, поэтому скрипт заодно заливает
RGB одним цветом латуни — весь тональный рисунок и так живёт в альфа-канале.
Это примерно вдвое сокращает вес и ничего не меняет визуально.

### Инфографика — отдельный случай

Её вырезать нельзя. У линейных иллюстраций тёмное — это фон, а здесь тёмное
это **содержимое**: глушитель снят как тёмный объект, панели шагов едва светлее
страницы, нижняя плашка ещё темнее. Порог по яркости съедает 57% фото, 80%
панелей и 88% плашки, а заливка от краёв протекает прямо в фото глушителя.

Поэтому чёрный у неё снимается не в файле, а при отрисовке — через
`mix-blend-mode: screen` на `.bdg-poster img`. Screen гасит подложку ровно там,
где она строго чёрная, поэтому `tools-cutout.py` сначала опускает чёрную точку
(`POSTER_BLACK = 16`): без этого над градиентом остаётся чуть более светлый
прямоугольник. Проверено — на границах постера расхождение с фоном страницы
не больше одного уровня, кромки не видно.

**Ограничения этого приёма** (те же, что были у иллюстраций): ни на одном
родителе не должно быть `transform` — он создаст stacking context, блендинг
отключится и чёрная плита вернётся; и страница за постером должна оставаться
тёмной. Здесь оба условия выполняются: постер статичен, в отличие от
иллюстрации в шапке.

⚠️ **Файл сам по себе НЕ прозрачный.** Чёрный снимается только на этой странице.
Если инфографика понадобится где-то ещё, особенно на светлом фоне — подложка
будет видна, и вырезать её придётся руками в редакторе: автоматически отделить
тёмное фото от тёмного фона не выходит.

Инфографика там же ужимается до 1300 px: шире колонка контента всё равно не бывает.

## Фон страницы

Страница не «просто тёмная»: по всей высоте идёт **один непрерывный градиент**,
построенный на графите магазина `#333333` — сверху глубокий графит `#26262A`,
к низу теплеющий и светлеющий до `#403C33`. Низ отдаёт золотом и заканчивается
тёплым акцентом в закрывающем блоке.

Из этого следует правило: **фоны секций и карточек — полупрозрачные подкраски,
а не сплошные цвета**. Сплошной блок пробил бы в градиенте плоскую дыру.
Для этого есть две переменные:

| Переменная | Что делает |
|------------|------------|
| `--lift` | секция читается приподнятой (белый 5%) |
| `--recess` | секция читается утопленной (чёрный 11%) |

По той же причине линии заданы через `rgba`, а не hex: фиксированный серый
растворился бы на светлом низу.

### Контраст

Раз фон по ходу страницы светлеет, светлый текст на нём темнеет по контрасту.
Все текстовые цвета проверены по WCAG в тех секциях, где реально используются.
На реальном рендере контраст **5.2–6.5** по всей странице.

Переход с чёрного на графит поднял фон примерно на 30 уровней и уронил три
цвета ниже нормы — все три пересчитаны, см. таблицу в `brand/brand.md`.
Главное: **тёмная латунь `--brass` больше не годится как текст** (3.66 на
графите), она осталась только для заливок, рамок и линий. Весь латунный текст —
`--brass-lit`. Счётчики списков в Terms и звёздочки `.bdg-ast` переведены
на неё же.

**Если будешь менять градиент — перепроверь контраст.** Достаточно сдвинуть
нижний стоп светлее, и мелкий текст в конце Terms уйдёт ниже нормы.

## Анимация

Вся анимация — на CSS, JS по-прежнему нет.

### Шапка появляется одной цепочкой

- **Заголовок** анимируется ТОЛЬКО цветом: слова прилетают латунными и остывают
  в белый за 1,5 с, со сдвигом 0,09 с друг за другом.

  ⚠️ Движения у заголовка быть не должно. Раньше слова ещё и всплывали снизу
  (`translate3d`), и на телефоне это давало заметное дрожание: сдвиг текста
  по вертикали заставляет браузер пересобирать глифы на каждом кадре.
  По той же причине снят `display:inline-block` — он был нужен только
  под transform.
- Дальше по заголовку непрерывно катится тёплая латунная волна —
  слово за словом слева направо, цикл 4,5 с.
  Для этого каждое слово в `<h1>` обёрнуто в `<span>` — «Gun&nbsp;Owners»
  оставлено одним span'ом, чтобы неразрывный пробел продолжал работать.
  Перенос строк не изменился: те же три строки.
- **Латунная линия** прочерчивается из-под последнего слова (`scaleX` от 0).
- Дальше по очереди — лид, строка про рибейт, кнопки.
- Иллюстрация идёт параллельно, вся последовательность укладывается в ~1,7 с.

Если будешь править текст заголовка — не забудь про `<span>` вокруг слов
и про правила `nth-child`, задающие задержки: слов там ровно пять.
У каждого слова **две задержки через запятую** — остывание цвета и волна.
Порядок менять нельзя.

Латунь на пике волны даёт контраст 7,77 при норме 3,0 для крупного текста —
запас большой, но если будешь менять оттенок, проверь.

### Иллюстрация

- **Появление** — иллюстрация в шапке всплывает и доворачивается до рабочего
  угла за 1,1 с после загрузки.
- **Дрейф** — дальше она покачивается, цикл 4,5 с.
- **Перелив** — по линиям постоянно течёт цвет, от меди к золоту и обратно,
  цикл 5 с туда-обратно. Устроен так: у выреза RGB залит одним цветом, весь рисунок сидит
  в альфа-канале, поэтому файл работает **маской**, а под неё подложен
  медленно едущий латунный градиент — цвет идёт по самим линиям.
  Размер градиента (150%) специально близок к размеру картинки: возьми сильно
  больше — на объект ляжет почти однотонный кусок, и вместо перелива получится
  равномерное мигание целиком.
- **Блик** — по латунным линиям раз в 8,5 с прокатывается световая полоса.
  Это копия картинки в псевдоэлементе `::after`, маскированная альфой самой
  картинки, поэтому свет идёт именно по линиям, а не по прямоугольнику.

⚠️ **Дрейф задан в ТРЁХ местах и везде должен совпадать:** у самой картинки,
у её варианта с маской внутри `@supports` и у псевдоэлемента с бликом.
Блик — отдельный слой поверх картинки, замаскированный её же альфой; разойдутся
длительности — маска уедет с объекта и свет пойдёт по пустому месту.

Периоды трёх анимаций разведены намеренно: дрейф 4,5 с, блик 8,5 с, перелив
5 с (туда-обратно 10 с). Отношения 1,89 и 2,22 — нецелые, поэтому рисунок
движения не повторяется и не читается механически. Раньше блик был 9 с, ровно
два цикла дрейфа, и всегда попадал в одну и ту же фазу.

Перелив спрятан под `@supports` на поддержку масок. Это не перестраховка:
без маски правило залило бы сплошной латунный прямоугольник вместо рисунка.
Браузер, который не умеет маскировать, просто показывает картинку как раньше,
без перелива.

## Картинки и размер окна

Все картинки на странице тянутся за шириной окна, ни одна не прячется:

| Картинка | 320px | 414px | 768px | 1440px |
|----------|-------|-------|-------|--------|
| Инфографика | 288 | 382 | 720 | 1112 |
| Иллюстрация в шапке | 91 | 137 | 279 | 468 |
| Иконка шага в ленте | 60 | 60 | 76 | 76 |

**Шапка не перестраивается на узких экранах.** Иллюстрация всегда справа
от текста и просто сжимается вместе со своей колонкой — ширину ей задаёт
не `max-width`, а доля в сетке `.bdg-herogrid`.

Так пришлось сделать после нескольких заходов. Сначала на ≤900px шапка
складывалась в одну колонку и картинка уходила наверх отдельным блоком —
она меняла место, а не размер. Потом ширина задавалась порогами и плато
(300/270/230px, затем потолок 330px) — между порогами размер не менялся вовсе.

Сейчас размер меняется на каждом шаге от 320 до 1160px:

| Экран | 320 | 414 | 560 | 800 | 1040 | 1160 |
|-------|-----|-----|-----|-----|------|------|
| Картинка | 91 | 137 | 193 | 279 | 422 | 475 |

Выше 1160px она не растёт — упирается `.bdg-wrap{max-width:1160px}`,
общий для всего содержимого страницы.

⚠️ **Доля колонки под картинку связана с кеглем заголовка.** У GOA самое
длинное слово заголовка было склеено неразрывным пробелом и не переносилось,
из-за чего долю колонки и кегль приходилось опускать вместе. Здесь заголовок
длинный («Welcome, Meprolight customers!») и разбит жёстким <br> после
первого слова, но дальше переносится свободно,
и такой связки нет. Правило остаётся: меняешь долю колонки — проверяй, как
встают слова заголовка на 320px.

У иллюстраций ~16% пустых полей с каждой стороны, поэтому при `contain` рисунок
занимает лишь две трети бокса. На широком экране это воздух, на узком картинка
теряется — масштаб задан переменной `--art-fit` (на узких экранах 136%).

⚠️ **`--art-fit` читают три правила сразу**: фон, маска варианта с `@supports`
и маска блика. Разойдутся — заливка перестанет совпадать с маской.

## Логотип Meprolight

Наверху страницы стоит логотип Meprolight, чтобы клиент партнёра сразу
узнал, куда попал. Логотип **вшит в файл**, а не подтянут с meprolight.com:
страница обязана быть самодостаточной, а хотлинк чужого CDN ненадёжен и грузит
их трафик. Взята белая версия (`logo_w.svg` на их сайте), исходники обеих —
в `assets/source/`.

**Здесь вшит вектор, а не растр** — в отличие от GOA и MasterFFL. У тех SVG
весил 86 КБ и растр честно выигрывал; этот после чистки экспортного мусора
(`id`, `data-name`) весит 6,6 КБ, то есть меньше любого разумного растра,
и подпись «SK GROUP MEMBER» под словом остаётся чёткой на любом экране —
в растре она на телефоне разваливается. `build.py` вшивает `.svg` наравне
с `.webp`; правило «растрируем векторное» остаётся в силе для тяжёлых
исходников.

**Размер:** `width:calc(var(--t-h1) * 4.382)`. Логотип встаёт ровно в ширину
слова «Welcome» из заголовка под ним — так просил клиент, так же сделано
у MasterFFL. Замер на восьми ширинах от 360 до 1440 дал 4,382 кегля
с разбросом 0,01 %: логотип и заголовок живут в одной шкале, отношение
не плавает, поэтому размер задан формулой от `--t-h1`, а не порогами.

Слово считается **без запятой** — запятая висячий знак, по ней не равняются;
с ней множитель был бы 4,678, на 64 px это лишние 19 px вправо.

⚠️ Множитель снят с конкретного слова: поменяется **первое слово** заголовка —
пересними. Остальной текст заголовка правится свободно.

⚠️ Оптический размер знака у партнёров при этом не общий: логотип Meprolight
составной, 1,7:1 против 3,1:1 у MasterFFL, и при равной ширине заметно
крупнее соседа. Это осознанно — привязка к слову важнее единообразия
между страницами.

⚠️ **Товарный знак партнёра.** Использование логотипа Meprolight согласовывает
клиент; это его решение, а не техническое. Если разрешение не оформлено —
логотип убирается одним блоком `.bdg-cobrand` в разметке и CSS.

⚠️ **Фирменный зелёный `#73c60a`** в знаке звучит громко на латунно-графитовой
странице. Трогать его нельзя — это цвет чужого знака.

## Низ инфографики: шаги и полоса апгрейда

Низ картинки перебран целиком — этим занимается `poster_layout.py`, его
вызывает `tools-cutout.py`. Четыре карточки Outlier стёрты, на их месте:

1. **шесть шагов клиента списком** с латунными номерами и волосками между
   пунктами — так же, как они выглядели живой вёрсткой на странице;
2. **компактная полоса** из трёх колонок под ними: «Want more performance»,
   «Go full auto. Go stainless» и сноска про ATF/NFA. Прежде полоса и сноска
   были двумя блоками с провалом между ними.

Текст набирается заново — четырёх карточек на шесть шагов не хватает, и тексты
стали длиннее. Шрифт **Barlow**, основной шрифт темы магазина (`brand/brand.md`).
Он же ближе всех к обычному начертанию самой инфографики: замер по трём строкам
известной ширины даёт расхождение 3,3%, всё системное расходится сильнее.
Файлы лежат в `assets/source/fonts/` вместе с лицензией OFL — чтобы сборка не
зависела ни от интернета, ни от того, что установлено на машине.

Иконки не рисуются, а берутся из исходников: диск со стрелкой и щит со звездой —
из полосы, щит с галочкой — из самой инфографики.

Кегль задан от того, как текст виден на странице, а не на глаз: картинка
показывается не шире 1112 CSS px при исходнике 1536, то есть уменьшается
в 0,72 раза. Прописная 26 px в исходнике даёт на экране 19 px — крупнее
основного текста страницы, потому что шаги здесь главное содержимое картинки,
а не подпись к ней. Шесть шагов таким кеглем в исходные 1024 px не помещаются,
поэтому **высота холста считается от содержимого** и картинка подросла
до 1536×1243 (в сборке 1300×1052).

Перенос строк выравнивается по длине: жадный перенос набивал первую строку
под завязку и оставлял в хвосте одно слово. После жадного прохода подбирается
самая узкая ширина, которая укладывается в то же число строк — строк не
прибавляется, а длина у них выравнивается. Оба блока набраны по одной сетке:
номер шага и иконка полосы стоят в колонке одной ширины, текст в обоих
начинается с одного x, волоски между шагами тянутся ровно на ширину рамки
полосы. Цвета сняты замером с самой инфографики, не подобраны.

⚠️ **Размеры в `<img>` заданы явно** — при любой правке текста высота картинки
меняется, и атрибуты надо менять вместе с ней, иначе страница дёрнется
при загрузке.

## ⚠️ Превью на GitHub Pages и мобильный вьюпорт

`bigcommerce-page.html` — **голый фрагмент**: ни `<!doctype>`, ни `<html>`,
ни `<head>`. Так и должно быть, его вставляют в поле «Page Content», а `<head>`
даёт тема магазина. Но у этого есть ловушка в превью.

Открытый напрямую с GitHub Pages, этот файл не несёт
`<meta name="viewport">`. Телефон в таком случае верстает страницу на 980 px
и уменьшает её до ширины экрана: **текст выглядит вдвое мельче, чем будет
в магазине, а колонка условий занимает две трети ширины** (её `max-width:59ch`
рассчитан на 980, а не на 390). Мобильные медиа-запросы при этом вообще
не срабатывают — вьюпорт-то 980.

Поэтому в `partners/meprolight/` лежит крошечный `index.html`: свой `<head>`
с вьюпортом и боевой файл в рамке на всю страницу. Внутри рамки вьюпорт равен
ширине экрана, и мобильная вёрстка видна такой, какой её увидит покупатель.
Указатель в корне репозитория ведёт именно на него.

**Смотреть мобильную версию только через `partners/meprolight/`**, не по прямой
ссылке на `bigcommerce-page.html`. В самом магазине проблемы нет.

### Ловушка специфичности — читать перед правкой отступов

Сброс `.bdg p,.bdg h1,…,.bdg ul,.bdg ol,.bdg li,.bdg figure{margin:0;padding:0}`
задан **по типу элемента**, поэтому его специфичность (0,1,1) выше, чем у любого
правила по одному классу (0,1,0). Он молча съедал заданные отступы у постера
и у соседних блоков — они слипались, и это выглядело как «поехавшая
вёрстка», а не как перебитое правило.

**Правило: любому `figure` / `ol` / `ul` / `li`, которому нужны свои отступы,
селектор пишем с именем тега** — например `figure.bdg-poster`.

### Про `prefers-reduced-motion`

Правило в конце `<style>` выключает всю анимацию разом. Поэтому **всё
анимируемое объявлено в нормальном, видимом состоянии**, а анимация только
уводит его оттуда и возвращает: иначе при выключенной анимации шапка осталась
бы пустой. По той же причине базовый угол `rotate(-8deg)` у иллюстрации задан
отдельно от кейфреймов — иначе картинка встала бы ровно.

Проверено: с включённым reduced-motion шапка рендерится точно так же, как
после отработавшей анимации.

## Форма «Claim Your Rebate» — куда она уходит

```html
<form class="bdg-form" method="post" enctype="multipart/form-data"
      action="https://verp.getoutlier.com/rebate-claim/">
```

Заявку принимает **Outlier VERP** — наша собственная система, а не сторонний
сервис форм. Что она делает за один запрос: записывает заявку, генерирует код
`ML-XXXXXX`, кладёт его в промо-акцию BigCommerce (промо 24, где уже настроена
скидка), отправляет SMS и письмо — и возвращает код на страницу.

**Ответ в JSON:**

```json
{"ok": true, "code": "ML-4K2P9X", "already_issued": false, "sms": true}
{"ok": false, "error": "…", "errors": {"email": ["Enter a valid email address."]}}
```

⚠️ **Запрос обязан слать `Accept: application/json`** — иначе сервер отвечает
готовой HTML-страницей с купоном. Так сделано намеренно: это запасной путь для
формы, отправленной без скрипта, и человек видит свой код, а не голый JSON.

⚠️ **Отвечает только этой витрине.** Сервер сверяет заголовок `Origin` с
`https://backdraftsuppressors.com` и чужой странице отказывает. Значит форму
нельзя проверить с локального файла или с другого домена — только с
опубликованной страницы магазина.

⚠️⚠️ **`www` — самая дорогая ошибка при запуске, проверить первым делом.**
Страница и эндпоинт живут на разных доменах, поэтому запрос кросс-доменный.
Он «простой» (multipart плюс `Accept` — оба в белом списке), предварительного
запроса браузер не шлёт, и **POST уходит на сервер в любом случае**. Прочитать
ответ браузер даст, только если в нём стоит `Access-Control-Allow-Origin`
с точным совпадением origin — посимвольно.

Не совпало — заявка записана, код выпущен, SMS ушло, а покупатель видит
«We could not reach the server» и жмёт Submit ещё раз. Спасает только то, что
сервер отдаёт тот же код повторно (`already_issued`).

Совпасть может не сразу: магазин вполне отдаёт страницу на
`https://www.backdraftsuppressors.com`, а в списке разрешённых стоит вариант
без `www`. Проверка — открыть опубликованную страницу и выполнить в консоли
`location.origin`; ровно эта строка должна быть разрешена на стороне VERP.
Вторая ловушка того же рода — редирект эндпоинта (`/rebate-claim` →
`/rebate-claim/`): после редиректа проверка origin ломается. В `action`
слэш на конце уже стоит, убирать его нельзя.

### Что страница показывает на каждый ответ

| Ответ сервера | Что видит покупатель |
|---|---|
| `ok: true` с кодом | Код на месте формы, кнопка «Redeem your rebate». Форма и заголовок секции скрыты |
| `ok: true`, `already_issued: true` | То же плюс «You have already claimed this rebate — this is the same code» |
| `ok: true`, `sms: false` | То же без фразы про SMS |
| `ok: true`, но код пустой | «Your claim is in» и совет дождаться письма. Форма скрыта: заявка-то принята |
| `ok: false` с `errors` | Каждая ошибка отдельной строкой, форма остаётся на месте — можно исправить и отправить снова |
| `ok: false` с `error` | Текст ошибки, форма на месте |
| Не JSON (500, заглушка защиты, отказ по размеру файла) | «Something went wrong on our side» — про нашу сторону, а не про интернет покупателя |
| Запрос не дошёл (сеть, CORS) | «We could not reach the server. Please check your connection» |

Тексты ошибок с сервера подставляются как **текст**, а не как разметка: если
в них однажды попадёт то, что ввёл покупатель, на витрине это останется
буквами. Код рибейта вдобавок чистится от всего, кроме букв, цифр и дефиса —
невидимый пробел с той стороны означал бы код, который не срабатывает на кассе,
а человек не понимает почему.

⚠️ **Акция включается вручную.** Пока её не включили на стороне VERP, форма
отвечает «This rebate programme is not open» — это нормальный ответ, а не
поломка. Включают после проверки префикса кодов и суточного потолка.

### Что приходит на сервер

Поля `name`, `email`, `phone`, `serial`, `proof`, `partner`, `sms_consent`
и ловушка `_gotcha`.

   `sms_consent` — одна галочка на две вещи сразу: согласие на SMS и
   подтверждение «мне 21 или больше». Галочка обязательная, поэтому приходит
   всегда со значением `yes`: без неё браузер форму не отправит. Хранить её
   всё равно нужно — это единственная запись о том, что человек и на рассылку
   согласился, и возраст подтвердил.

   ⚠️ Возраст здесь ПОДТВЕРЖДАЮТ, а не проверяют: страница его не знает и
   узнать не может. Документ смотрит FFL/SOT при передаче глушителя.

   ⚠️⚠️ **Юридический риск, принят клиентом.** Галочка обязательная, а в её
   тексте — согласие на маркетинговые SMS. Значит без согласия на рекламу
   рибейт не получить, а по правилам США (TCPA) требовать согласия на
   маркетинговые сообщения как условие получения выгоды нельзя. Если юрист
   клиента это завернёт — развести обратно на две галочки (возраст
   обязательный, SMS добровольное) стоит пяти строк в `page.src.html`; так
   было сделано в коммите 797805e, оттуда и копировать.

   ⚠️ Поля даты рождения в форме нет — клиент попросил убрать. Если сервис
   рассылки SMS (SlickText) не заводит подписчика без даты рождения, галочка
   его не заменит: дату придётся либо собирать в его собственном шаге
   подтверждения подписки, либо вернуть поле в форму.

Поле `partner` со значением `Meprolight Optics` сервер сверяет со своей
настройкой: разойдутся — заявка будет отклонена, а не принята «куда-нибудь».

Ловушку `_gotcha` сервер отбрасывает сам, как и повторный сабмит той же
формы в пределах двух минут — он возвращает тот же код, а не печатает второй.
Купил у партнёра ещё раз позже — получит новый код, это не «один на человека».

**Файл чека:** любая картинка и PDF, до 25 МБ. Проверяется по типу содержимого,
а не по расширению — фото, присланное из другого приложения, приходит с именем
`blob` и без расширения вовсе.

⚠️ **Проверить сразу после вставки в BigCommerce**, что тема не вырезала `<form>`
и не завернула страницу в свою форму: вложенная `<form>` внутри чужой `<form>`
браузером игнорируется, и кнопка молча перестанет работать. Смотреть через
«Просмотр кода» на опубликованной странице, а не в админке.

⚠️ Данные персональные (имя, телефон, почта, чек). Куда они уходят и кто к ним
имеет доступ — решение клиента, а не наше.

## «Серийник ИЛИ чек» — единственный скрипт на странице

Что обязательно в форме: имя, почта, телефон, галочка согласия — и **хотя бы
одно** из пары «серийный номер / подтверждение покупки». Первые четыре стережёт
сам браузер атрибутом `required`. Правила «хотя бы одно из двух» в HTML нет,
поэтому в конце фрагмента лежит десяток строк скрипта: пока оба поля пусты, он
выставляет им текст ошибки «Enter the serial number or attach your proof of
purchase», и форму не пускает всё тот же встроенный механизм проверки — с родной
подсказкой браузера, на языке покупателя. Заполнили любое из двух — ошибка
снимается.

Это единственный JS на странице; всё остальное по-прежнему работает без него.

⚠️ **ПРОВЕРИТЬ СРАЗУ ПОСЛЕ ВСТАВКИ В BIGCOMMERCE.** Редактор страницы вырезает
теги, которые считает опасными, и `<script>` — первый кандидат (`<style>` он
вырезает точно, если вставлять не в режиме HTML-источника). Проверка занимает
полминуты: открыть опубликованную страницу, заполнить имя, почту, телефон,
поставить галочку, оставить серийник и чек пустыми и нажать Submit. Если форма
ушла — скрипт вырезан.

⚠️ **Если скрипт не выполнится — форма НЕ ломается.** Она останется полностью
рабочей и просто перестанет стеречь это одно правило, как было до 12.09.2026:
заявка сможет прийти без серийника и без чека. Сделано намеренно — молча не
отправляющаяся форма хуже, чем форма, пропускающая неполную заявку.

Поэтому подстраховаться на стороне обработчика всё равно стоит: большинство
сервисов форм умеет отбрасывать или помечать заявку, где пусты оба поля. Это
две минуты настройки и единственная защита от покупателя с отключённым JS.

### Если BigCommerce вырезал скрипт — запасной путь

У магазина есть штатное место для скриптов, которое ничего не вырезает:
**Storefront → Script Manager → Create a Script**.

| Поле | Что поставить |
|------|---------------|
| Name | `Meprolight rebate form rule` |
| Location on page | `Footer` |
| Select pages | `Specific Pages` → страница `/meprolight` |
| Script type | `Script` |
| Script category | `Essential` |

В поле кода вставить ровно это — тот же текст, что лежит в конце
`page.src.html`, включая теги:

```html
<script>
(function () {
  function init() {
    var form = document.querySelector('.bdg-form');
    if (!form) return;
    var serial = form.querySelector('#bdg-serial');
    var proof = form.querySelector('#bdg-proof');
    if (!serial || !proof || !serial.setCustomValidity) return;

    function check() {
      // .files есть везде, где есть setCustomValidity; проверка на всякий случай
      var filled = serial.value.trim() !== '' ||
                   (proof.files ? proof.files.length > 0 : proof.value !== '');
      var message = filled ? '' : 'Enter the serial number or attach your proof of purchase.';
      serial.setCustomValidity(message);
      proof.setCustomValidity(message);
    }

    serial.addEventListener('input', check);
    proof.addEventListener('change', check);
    check();   // на загрузке: оба пусты, значит форма уже несдаваемая

    /* Отправка без ухода со страницы.

       Без этого куска форма всё равно рабочая: браузер уйдёт на verp и покажет
       купон там, не на нашей странице. Но уход с витрины рвёт сессию и корзину
       покупателя, поэтому запрос идёт фоном, а ответ рисуется на месте формы.

       ⚠️ Браузер без fetch или FormData ничего не перехватывает и отправляет
       форму обычным способом. Это и есть запасной путь, а не поломка. */
    if (!window.fetch || !window.FormData) return;

    var btn = form.querySelector('button[type="submit"]');
    if (!btn) return;
    var label = btn.textContent;

    var out = document.createElement('div');
    out.className = 'bdg-result';
    /* Блок рождается уже после загрузки страницы, и экранный диктор сам его не
       заметит: код появится молча. role/aria-live заставляют прочитать его. */
    out.setAttribute('role', 'status');
    out.setAttribute('aria-live', 'polite');
    out.hidden = true;
    form.parentNode.insertBefore(out, form.nextSibling);

    /* Заголовок секции — «Submit Meprolight Proof of Purchase…». Когда форма
       уступает место коду, он начинает врать, поэтому прячется вместе с ней. */
    var heading = form.previousElementSibling;
    if (!heading || heading.tagName !== 'H2') heading = null;

    /* Узлы собираются DOM-методами, а текст кладётся через textContent.
       Это не стилистика: строки ниже приходят с сервера, и склейка их
       в innerHTML означала бы, что любой текст оттуда исполняется на витрине
       магазина как разметка. Полагаться на то, что на том конце ничего
       никогда не поменяется, — не наша роль. */
    function el(tag, className, text) {
      var node = document.createElement(tag);
      if (className) node.className = className;
      if (text) node.textContent = text;
      return node;
    }

    function show(nodes) {
      while (out.firstChild) out.removeChild(out.firstChild);
      for (var i = 0; i < nodes.length; i++) out.appendChild(nodes[i]);
      out.hidden = false;
      out.scrollIntoView({ behavior: 'smooth', block: 'center' });
    }

    /* Копирование кода. Код набирают руками на кассе, и ошибиться в нём легко:
       кнопка рядом надёжнее, чем выделять мышью мелкий текст на телефоне.

       Три ступени, сверху вниз: современный clipboard API; старый execCommand
       для браузеров без него и для страниц, открытых не по https; а если не
       вышло и это — код просто выделяется, человеку остаётся нажать копирование
       самому. Молча не делать ничего нельзя: нажали кнопку — что-то должно
       произойти. */
    function flash(button, text) {
      button.textContent = text;
      button.className = 'bdg-copy is-done';
      clearTimeout(button.timer);
      button.timer = setTimeout(function () {
        button.textContent = 'Copy';
        button.className = 'bdg-copy';
      }, 2000);
    }

    function legacyCopy(text) {
      var ta = document.createElement('textarea');
      ta.value = text;
      /* Уведено за край, а не спрятано правилом: из скрытого display:none поля
         выделять нечего, и копирование вернёт пустоту. readonly — чтобы на
         телефоне не выезжала клавиатура. */
      ta.setAttribute('readonly', '');
      ta.style.position = 'absolute';
      ta.style.left = '-9999px';
      ta.style.top = '0';
      document.body.appendChild(ta);
      ta.select();
      var ok = false;
      try { ok = document.execCommand('copy'); } catch (err) { ok = false; }
      document.body.removeChild(ta);
      return ok;
    }

    function selectNode(node) {
      try {
        var range = document.createRange();
        range.selectNodeContents(node);
        var sel = window.getSelection();
        sel.removeAllRanges();
        sel.addRange(range);
      } catch (err) { /* выделить не вышло — код и так на экране */ }
    }

    function copyButton(text, codeNode) {
      var button = el('button', 'bdg-copy', 'Copy');
      /* ⚠️ type обязателен: кнопка вне формы, но тема магазина может завернуть
         страницу в свою, и тогда кнопка без type отправит её. */
      button.type = 'button';

      function fallback() {
        if (legacyCopy(text)) { flash(button, 'Copied'); return; }
        selectNode(codeNode);
        button.textContent = 'Select & copy';
      }

      button.addEventListener('click', function () {
        if (navigator.clipboard && navigator.clipboard.writeText) {
          navigator.clipboard.writeText(text).then(function () {
            flash(button, 'Copied');
          }, fallback);
          return;
        }
        fallback();
      });
      return button;
    }

    function showError(texts) {
      var nodes = [];
      for (var i = 0; i < texts.length; i++) {
        nodes.push(el('p', 'bdg-result-error', texts[i]));
      }
      show(nodes);
    }

    var sending = false;

    /* ⚠️ submit не наступает, пока форма невалидна, — значит check() выше
       по-прежнему стережёт «серийник или чек», и переносить его не пришлось. */
    form.addEventListener('submit', function (e) {
      e.preventDefault();

      /* ⚠️ Не лишняя проверка: Enter в текстовом поле отправляет форму даже
         тогда, когда кнопка выключена. Без флага уходил бы второй запрос —
         и второе SMS покупателю. */
      if (sending) return;
      sending = true;

      btn.disabled = true;
      btn.textContent = 'Sending\u2026';

      /* Различаем «не достучались» и «ответили не тем»: покупателю незачем
         проверять свой интернет, когда упал наш сервер. */
      var reached = false;

      fetch(form.action, {
        method: 'POST',
        body: new FormData(form),
        /* ⚠️ Без этого заголовка сервер отвечает целой HTML-страницей — так
           устроен запасной путь для формы без скрипта. Здесь нужен JSON. */
        headers: { 'Accept': 'application/json' }
      })
        .then(function (r) {
          reached = true;
          /* Не по r.ok: отказ по полям приходит статусом 422 и тоже JSON,
             его надо разобрать и показать. А вот не-JSON — это уже не наш
             протокол: 500, заглушка защиты, отказ из-за размера фото.
             Content-Type читается и с чужого домена, разрешения не нужно. */
          var type = r.headers.get('content-type') || '';
          if (type.indexOf('json') === -1) throw new Error('not json');
          return r.json();
        })
        .then(function (b) {
          if (!b || !b.ok) {
            var texts = [];
            if (b && b.errors) {
              for (var k in b.errors) {
                if (Object.prototype.hasOwnProperty.call(b.errors, k)) {
                  texts = texts.concat(b.errors[k]);
                }
              }
            }
            if (!texts.length) {
              texts = [(b && b.error) || 'Something went wrong. Please try again.'];
            }
            showError(texts);
            return;
          }

          /* Код набирают руками на кассе, поэтому из него выбрасывается всё,
             кроме букв, цифр и дефиса: невидимый пробел с той стороны — это
             код, который не сработает, а человек не поймёт почему. */
          var code = String(b.code || '').replace(/[^A-Za-z0-9-]/g, '');

          form.hidden = true;
          if (heading) heading.hidden = true;

          /* Заявка принята, а кода в ответе нет. Так быть не должно, но пустой
             блок под заголовком «Your rebate code» — худшее, что можно
             показать: человек решит, что всё сломалось, хотя код уже выпущен
             и уходит письмом. */
          if (!code) {
            show([
              el('p', 'bdg-result-title', 'Your claim is in'),
              el('p', 'bdg-result-note', 'Your code did not come back with this reply, ' +
                 'but a copy is on its way to your email. If it does not arrive within ' +
                 'an hour, contact us.')
            ]);
            return;
          }

          var note = b.already_issued
            ? 'You have already claimed this rebate — this is the same code. ' +
              'Enter it at checkout to redeem.'
            : 'Enter this code at checkout to redeem.' +
              (b.sms ? ' We have also sent it to your phone.' : '') +
              ' A copy is on its way to your email.';

          var link = el('a', 'bdg-btn bdg-btn--solid', 'Redeem your rebate');
          link.href = 'https://backdraftsuppressors.com/backdraft-hunter/';

          var codeNode = el('p', 'bdg-result-code', code);
          var codeLine = el('div', 'bdg-result-codeline');
          codeLine.appendChild(codeNode);
          codeLine.appendChild(copyButton(code, codeNode));

          show([
            el('p', 'bdg-result-title', 'Your rebate code'),
            codeLine,
            el('p', 'bdg-result-note', note),
            link
          ]);
        })
        .catch(function () {
          showError([reached
            ? 'Something went wrong on our side. Your claim may not have gone through — ' +
              'please try again in a few minutes.'
            : 'We could not reach the server. Please check your connection and try again.']);
        })
        .then(function () {
          sending = false;
          btn.textContent = label;
          btn.disabled = false;
        });
    });
  }

  /* Ждать разметку, если код выполняется раньше неё. Здесь, в конце фрагмента,
     форма уже существует и init() пойдёт сразу. Ожидание нужно не для этого
     места, а для запасного: если BigCommerce вырежет скрипт из страницы, ровно
     этот же код кладётся в Script Manager, а он вставляет его в <head>, то есть
     до формы. Так один и тот же текст работает в обоих местах без правок. */
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', init);
  } else {
    init();
  }
})();
</script>
```

Код специально написан так, чтобы работать в обоих местах без правок: если
разметки ещё нет, он дожидается её события `DOMContentLoaded`. Поэтому в
Script Manager годится и `Footer`, и `Header`.

После сохранения — та же проверка: заполнить имя, почту, телефон, поставить
галочку, серийник и чек оставить пустыми, нажать Submit. Форма не должна уйти.

⚠️ Скрипт в Script Manager живёт отдельно от страницы: правка `page.src.html`
и пересборка его НЕ меняют. Если правило когда-нибудь поменяется, менять
придётся в двух местах. `build.py` сверяет код на странице с копией в этом
файле и падает, если они разошлись, — но про Script Manager он не знает.

## Если тема вырезает `<style>`
Некоторые сборки Stencil чистят inline-стили. Тогда содержимое `<style>`
переносится в файл темы `assets/scss/_partner-goa.scss` и импортируется
в `theme.scss`, а в страницу остаётся только разметка. Селекторы уже
изолированы под `.bdg`, переносить можно как есть.

## Как править страницу

**Правится `page.src.html`, а не `bigcommerce-page.html`.** Второй генерируется
и весь забит base64 — редактировать его руками бессмысленно.

```
python3 build.py          # из папки partners/meprolight, нужен только стандартный Python
```

Скрипт подставляет картинки как data URI и пишет два файла:

| Файл | Зачем |
|------|-------|
| `bigcommerce-page.html` | вставлять в BigCommerce |
| `preview.html` | открыть локально, добавлен макет шапки/футера магазина |

Превью можно открыть прямо двойным кликом — картинки внутри файла,
сервер не нужен.

`tools-cutout.py` перезапускать не нужно: он готовит содержимое `assets/`
из `assets/source/` и требует Pillow. Запускать только если поменялись
исходные иллюстрации.

Тексты — в `copy.md`.
